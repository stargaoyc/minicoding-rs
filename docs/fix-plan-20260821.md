## Sprint 0：安全止血（目标版本 v0.2.32，含 BREAKING）

> 目标：消除两个"严重"与三个最高危"高"。全部为外部可触达路径，独立成版便于回滚。

### F-S1【严重】server 全端点加鉴权

- **根因**：http.rs:300-329 路由无 auth 中间件；任何本机进程可代答权限、读全会话。
- **方案**：
  1. `crates/minicoding-server/src/main.rs`：启动时生成 token（`rand` 32B hex；workspace
     已有 rand 传递依赖则直接用，否则 ulid 两拼接）；
     优先级：`--auth-token <t>` 参数 > 自动生成并打印首行 `SERVER_TOKEN=<t>`；
     `--no-auth` 显式关闭（stderr 红字三行警告 + audit.log 记一条 `ConfigChanged`）。
  2. http.rs 新增 axum middleware `require_auth`：校验 `Authorization: Bearer <t>`（常量时间
     比较 `subtle` 或手写字节异或累积比较）；豁免路径仅 `/health`。
  3. 客户端适配：
     - Web 直连模式：`VITE_API_TOKEN` 注入 client.ts 的 `apiBase` 同级 `authToken`；
     - Vite dev proxy 模式：proxy 目标本机免鉴权（token 由 proxy 侧附加）；
     - Tauri sidecar：启动参数传 token（内存传递，C-04 兼容，见 sidecar.rs:26 现有约定），
       tauri.ts invoke 时读取。
  4. SSE/NDJSON：EventSource 不能带 header——token 以查询参数 `?token=` 接受（仅这两个
     端点，日志脱敏 query）。
- **验收**：集成测试 `server/tests/auth.rs`：无 token 401 / 错 token 401 / `/health` 豁免 /
  正确 token 全端点通 / `--no-auth` 时全通且审计有记录。
- **文档**：getting-started/product-manual 补 curl 示例；release note 标注 BREAKING。
- **工作量**：M｜**依赖**：无

### F-S2【严重】CORS 默认收敛 localhost

- **根因**：http.rs:283-288 空列表渲染为 Any；main.rs:62-64 注释与 AGENTS.md §8.6 相反。
- **方案**：`cors_origins` 为空时默认注入 `["http://localhost", "http://127.0.0.1"]`（any port）；
  `--cors-origin` 追加显式来源；Any 语义彻底移除（传 `*` 报错提示用具体来源）。
- **验收**：单测断言空配置构建出的 CorsLayer 拒绝 `https://evil.com` origin 预检；
  集成测试带 Origin 头跨域 403。
- **工作量**：S｜**依赖**：无（与 F-S1 叠加防御）

### F-S3【高】full-access preset 经 API 需显式二次确认

- **根因**：http.rs:456-458,478-485 仅日志即生效，C-22 在 server 路径退化。
- **方案**：`CreateSessionBody` 增加 `confirm_danger: Option<bool>`；
  preset ∈ {full-access, external-sandbox} 且 `confirm_danger != Some(true)` → 400，
  错误消息指引用户在 UI 二次确认。前端 W-11 既有确认弹窗在确认后携带该字段；
  决策落 audit.log（`AuditKind::PermissionResolved`, detail=`danger_preset_confirmed`）。
- **验收**：集成测试：缺 confirm 400；带 confirm 创建成功且有审计记录。
- **工作量**：S｜**依赖**：无

### F-S4【高】modify_input 后对修改后输入重跑策略（修 C-01/C-21 缺口）

- **根因**：rt.rs:1384 check 原始 call → :1689 Hook 替换 input → :1450 执行改后输入；
  黑名单/路径策略对最终输入从未生效，审计失真。
- **方案**（rt.rs `execute_side_effect_call` 流程重排）：
  1. 原 check 保留（产出 verdict_0 供 Hook 输入构造）；
  2. PreToolUse Hook 执行后，若 `effective_call.input != original_call.input`：
     对 effective_call 重跑 `policy.check` 得 verdict_1，**取两者较严者**
     （序：Deny > Ask > Allow；Ask 与 Allow 并存取 Ask；两条 Deny 任一生效即 Deny）；
  3. 后续 Prompter/审计全部基于合并后 verdict 与 effective_call.input；
  4. 审计 record 的 detail 增加 `"input_modified": true`。
  只读桶不涉及 modify_input（Hook 分发仅在副作用路径，现状已然）。
- **验收**：agent_loop.rs 新增集成测试：
  `hook_modify_input_to_blacklisted_command_denied`（Hook 把 ls 改 rm -rf AGENTS.md → Deny 回灌）、
  `hook_modify_input_path_escape_rechecked`（改 path 至 workdir 外 → PathEscaped/Deny）、
  `hook_modify_input_audit_records_final_input`。
- **工作量**：M｜**依赖**：建议先落 F-S5（黑名单扩展后本修复才有"牙"，可同 Sprint 并行开发）

### F-S7【高】LKG 配置剥离明文凭证 + 0600

- **根因**：config.rs:340-348 在 resolve_env_vars 之后序列化落盘，明文 key 0644。
- **方案**：
  1. 写 LKG 前深拷贝 cfg，将 `provider.api_key`、`provider.small.api_key` 置空串
     （LKG 仅用于"解析失败回退保证能启动"，缺 key 时 provider 报 NotConfigured 引导重配，
     安全优先；文档注明此行为变化）；
  2. 写盘统一走新 helper `write_private(path, bytes)`：unix `set_permissions(0o600)`
     （先 create 再 chmod，防竞态窗口用 OpenOptions mode 0o600 创建）；windows 保持默认 ACL；
  3. 该 helper 同时供 audit.rs 复用（收敛权限处理）。
- **验收**：单测（隔离 MINICODING_HOME + unsafe set_var，沿用 desktop config 测试的 ENV_LOCK
  模式）：env 设 key → load_config 成功 → 读 .last-known-good.toml 内容不含明文且
  unix 权限 600。
- **工作量**：S｜**依赖**：无

**Sprint 0 验收门禁**：cargo fmt/clippy/test 全绿 + 新增测试全过 + `cargo audit` +
手动冒烟（serve 起服 → curl 无 token 401 → 带 token 通 → 网页跨域被拒）。

## Sprint 1：权限与资源加固（目标版本 v0.2.33）

### F-S5【高】内置黑名单覆盖 shell 类保护目标

- **根因**：builtin.rs:237-242 仅 fs.delete 删约束文件；shell 旁路全开；.git 无应用层补偿。
- **方案**（builtin.rs）：
  1. 新增 `fn normalize_tokens(cmd: &str) -> Vec<String>`：空白切分 + 剥引号 + 合并
     `\=` 赋值前缀；不做完整 shell 解析（诚实边界：base64|sh 变形不在黑名单能力内，
     由沙箱+用户审批兜底，security.md 注明）；
  2. 规则一（约束文件）：cmd 中出现 `rm`/`mv`/`sed -i`/`truncate`/`dd` 且任一后续 token
     以 AGENTS.md/CLAUDE.md 结尾，或重定向符 `>`/`>>` 后紧邻 token 为约束文件 → Deny；
  3. 规则二（VCS 元数据）：fs.write/fs.delete 的 sandbox_path 任一组件 ∈ {.git,.hg,.svn}
     → Deny；shell.run cmd 中出现 `.git/hooks/` 等写暗示（hooks/ 目录 + 重定向/tee）→ Deny；
  4. 复用 sandbox crate 已有的 `vcs_protected_dirs` 常量（现未被引用）避免双份定义——
     policy 不能依赖 sandbox（领域交叉），将常量上移至 core::sandbox 或复制并注释同源。
- **验收**：policy 单测：`rm AGENTS.md` / `echo x > AGENTS.md` / `fs.write .git/hooks/pre-commit`
  均 Deny 且 Hook Allow 不可覆盖（沿用 C-21 测试骨架）；正常 `cat AGENTS.md` 读不受限。
- **工作量**：M｜**依赖**：无

### F-S6【高】plan.exit 预批准缓存改词法比对

- **根因**：builtin.rs:127-142 `contains` 子串匹配可拼接绕过。
- **方案**：缓存命中条件改为——`tokens(cmd)` 与 `tokens(prompt)` 完全相等，或 cmd tokens
  以 prompt tokens 开头（词边界）；cmd 含 `;`/`&&`/`|`/反引号/`$(` 且 prompt 不含时直接
  不命中（复合命令永不继承预批准）。
- **验收**：更新既有测试 + 新增：`echo cargo test` 拼接不命中；`cargo test --nocapture`
  词边界前缀命中；`cargo test && rm x` 不命中。
- **工作量**：S｜**依赖**：F-S5 的 tokenize helper 复用

### F-S8/F-S9/F-S10【高】shell.run 资源三连修

- **S8 超时 clamp**：run.rs:100-103 改
  `effective = min(args.timeout_ms.unwrap_or(ctx.timeout), ctx.timeout)`——工具入参只能缩短
  不能超过 ToolContext 上限（ctx.timeout 已由 Runtime 按 config.shell_timeout_sec 注入，
  schema description 注明"上限为会话配置"）。
- **S9 进程组**：unix 在现有 pre_exec 硬化闭包（linux.rs/hardening 同款机制）追加
  `libc::setpgid(0, 0)`；超时路径改 `libc::killpg(pgid, SIGKILL)`（tokio Child id 取 pid 后
  spawn_blocking 执行）；Windows 维持 Job Object kill_on_drop（树杀已覆盖），补注释说明
  平台差异。macOS 同 unix 路径。
- **S10 流式截断**：run.rs 弃 `wait_with_output`，改 `BufReader` 逐行/逐块读 stdout/stderr
  两个 task，累计字节 > `ctx.max_output_bytes * 2` 即停止读取置 truncated（进程继续至退出
  或超时，避免 SIGPIPE 提前暴露）；fetch.rs 改 `bytes_stream()` 逐 chunk 累计同一上限。
- **验收**：集成测试（tools crate）：`timeout_clamped_to_context_limit`（args 传 u64::MAX
  实际 120ms 内返回）；`background_orphans_killed_on_timeout`（`sleep 3600 &` 超时后
  pgrep 无残留进程——unix only cfg）；`output_truncated_streaming_no_oom`（yes | head 压测
  内存峰值断言，或简化为截断标志正确）。
- **工作量**：M+M+S｜**依赖**：无
